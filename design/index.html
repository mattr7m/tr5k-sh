Backcountry Network Monitoring with LoRa

Feb 18, 2026 camping infra

Last fall I spent a week in the Boundary Waters with a couple of Heltec V3 boards, a small solar panel, and an unreasonable desire to know the temperature of the lake at all times. This is what I learned about running a LoRa mesh network when the nearest cell tower is 40 miles away.

The Hardware

The Heltec WiFi LoRa 32 (V3) hits a good balance between cost and capability. At roughly $18 per board you can afford to lose one to a curious raccoon. I flashed each with Meshtastic firmware and packed them in waterproof cases from the dollar store.

Note

If you're considering the TTGO T-Beam as an alternative, be aware that the GPS module draws significantly more power. For stationary nodes, the Heltec is the better choice.

Node Configuration

Each node was configured with a 60-second broadcast interval. The base station sat under a tarp near camp, powered by a 6W panel feeding a small LiFePO4 cell:

# meshtastic config for base node
meshtastic --set lora.region US
meshtastic --set lora.modem_preset LONG_SLOW
meshtastic --ch-set name "bwca-mesh"
meshtastic --set position.gps_enabled false
meshtastic --set power.wait_bluetooth_secs 30

The remote nodes were placed at the portage landing and the far shore — roughly 1.2km line-of-sight across the lake. Signal strength held surprisingly well over water, averaging around -95 dBm.

Bypassing Rate Limits with HTTP/2 Single-Packet Attacks

Mar 02, 2026 exploits

Most rate-limiting implementations count requests sequentially. But HTTP/2's multiplexing lets you stuff multiple requests into a single TCP packet, and many servers will process them all before the rate limiter fires. Here's how that works in practice and why it matters for your pentest methodology.

The Mechanics

HTTP/2 allows multiple streams within one connection. The trick is to prepare all your request frames, then flush them to the socket in one write() call. The server's TCP stack delivers the entire packet to the application layer at once, and most frameworks will parse and dispatch all streams before any middleware (including rate limiters) can react.

# using h2 library for single-packet attack
import h2.connection
import socket

conn = h2.connection.H2Connection()
conn.initiate_connection()

# prepare 50 streams before flushing
for i in range(50):
    sid = conn.get_next_available_stream_id()
    conn.send_headers(sid, headers)
    conn.send_data(sid, payload)

# single flush — single packet
sock.sendall(conn.data_to_send())

In testing against three common WAF products, this technique bypassed rate limits in two out of three. The one that caught it was doing connection-level accounting rather than request-level — a much more robust approach.

Migrating My Homelab to NixOS: A Postmortem

Feb 25, 2026 homelab nix

After three years of Ansible playbooks accumulating like sediment, I finally moved the homelab to NixOS. The migration took a weekend, broke DNS twice, and I'd do it again in a heartbeat. Here's the full story.

Why NixOS

The appeal is declarative system configuration with atomic rollbacks. My Ansible setup had drifted enough that I couldn't reliably rebuild a node from scratch — the classic "works on my infrastructure" problem. NixOS solves this by treating the entire system state as a function of your config files.

Lesson Learned

Don't migrate your DNS server first. I moved the Pi-hole replacement (blocky on NixOS) before anything else, which meant every failure cascaded into "can't resolve anything." Move DNS last.

The Fleet

Three nodes running on recycled Dell Optiplex machines: one as a NAS with ZFS, one running k3s for services, and one dedicated to monitoring (Prometheus + Grafana). Total power draw sits around 85W, which keeps the monthly cost under $8.

# flake.nix — simplified
{
  outputs = { nixpkgs, ... }: {
    nixosConfigurations = {
      nas    = mkHost ./hosts/nas.nix;
      compute = mkHost ./hosts/compute.nix;
      monitor = mkHost ./hosts/monitor.nix;
    };
  };
}

The entire config lives in a single git repo. Deploying to all three nodes is one command: nixos-rebuild switch --flake .# on each, or using deploy-rs for remote pushes. Rollback is just booting the previous generation from GRUB.
